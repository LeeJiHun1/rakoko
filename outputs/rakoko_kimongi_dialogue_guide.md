# 키몽이 집단 대사·반응 가이드

2026-11-05 · v1.1 · 다수 전제는 사용자 확정, 연출 수치는 구현 기본안

키몽이는 라코코를 보는 여러 시청자다. 기본 에셋 하나가 키몽이라는 단일 인물을 뜻하지 않는다. 방송 화면에서는 여러 키몽이가 짧게 반응하고, 일부는 질문하거나 농담을 받아치며, 일부는 지켜본다. 집단의 말투 자료와 개별 가상 NPC의 성격 설정을 구분한다.

## 조사 범위

치지직 공개 다시보기 10개에서 각각 90초짜리 6구간을 수집했다. 초반, 10분, 30분, 전체 길이의 50%·75%, 끝에서 5분 전을 시작점으로 삼았다. 총 60구간·90분이며, 7,256건은 자동 필터 후 남은 메시지 수다. 서로 다른 시청자 7,256명이라는 뜻이 아니다. 2026-09-09~11-02 게시 영상의 편의 표본이므로 1월부터의 변화나 전체 팬덤의 분포를 설명하지 않는다.

원문과 재생 시각의 존재를 확인했으며 해당 영상의 음성·화면과 대조하지 않았다. 방송 제목은 후보 맥락이고, 채팅에 쓰인 예상·농담은 실제 방송 결과를 입증하지 않는다. [수집 보고서](rakoko_kimongi_chat_research.md)에 영상별 범위와 근거를 기록한다.

## 집단을 쓰는 방식

반응의 기능은 다음처럼 나눈다. 아래 항목은 대사 작성 도구이며 실제 팬을 고정된 성격 유형으로 분류한 결과가 아니다. 한 가상 키몽이도 상황에 따라 여러 기능을 수행할 수 있다.

|기능|용도|문장 길이 기본안|
|---|---|---|
|입장·인사|새 방송에 들어오기|2~12자|
|웃음·맞장구|흐름을 만들기|1~10자|
|가벼운 놀림|실수나 예상 밖 전개 받아치기|6~24자|
|질문·뒤늦은 합류|맥락을 묻기|6~28자|
|관찰·정정|눈에 보이는 변화 짚기|8~30자|
|응원·기대|시도 중 격려하기|4~24자|
|성공·축하|실제 성공·해금 뒤 반응|2~24자|
|실패·수습|아쉬움과 다음 시도 제안|4~28자|
|취향·의견 차이|선택에 다른 선호 드러내기|6~28자|
|콜백·약속 기억|이번 run에서 겪은 일 회수|8~32자|
|감상·고마움|기념일·일지·마무리|6~32자|
|퇴장·관망|끝인사·작은 표정 반응|0~18자|

평상시 반응 묶음은 3~5줄, 최소 두 가상 화자를 기본으로 한다. 조용한 장면은 0~2줄도 허용한다. 웃음만 길게 채우거나 전원이 장문으로 설명하지 않는다. 실제 표본 비율을 그대로 추첨 확률로 복사하지 않는다. 축하 장면의 합창은 허용하되 취향 선택에서 “키몽이 전원이 찬성”처럼 집단 전체의 의사를 단정하지 않는다.

새로운 필수 클릭이나 시간 대기는 추가하지 않는다. 사건 결과와 함께 반응을 펼치고, 즉시 전체 표시·반응 접기를 제공한다. 보통 사건의 기본 표시는 3줄이며 5줄은 공개·성공 등 강조할 때 사용한다. 감정 연출 때문에 기존 15~25분 플레이타임 목표를 늘리지 않는다.

## 대사 맥락과 잠금

- 공개 전 의상명·전신 모양을 아는 대사는 사용하지 않는다. 부분 유출이면 실제로 보인 단서만 말하고, 정체를 맞혔다는 사실을 만들어내지 않는다.
- 공략은 현재 gameId·진행도에서 확인된 정보만 제공한다. 알아야 할 필수 조건은 UI에도 표시하고 채팅 운에 맡기지 않는다.
- 성공 대사는 실제 결과 확정 뒤 사용한다. 진행 중이면 기대·예상으로 표현한다.
- 콜백은 같은 run의 경험·약속 ID를 요구한다. 날짜 도약만으로 참여·목격·친분을 생성하지 않는다.
- 잔액 부족으로 유료 사건을 포기했으면 다음 기회를 말할 수 있으나 구매·납품·기획 완성을 축하하지 않는다.
- 대사가 스테이터스·현금·경험을 직접 지급하지 않는다. 보상과 엔딩은 기존 사건 결과 규칙이 결정한다.

## 화자와 에셋

채팅에 보이는 이름은 게임이 만든 `키몽이 01` 등의 가상 표시다. 실제 닉네임·프로필·말버릇 소유자를 재현하지 않는다. 반복해서 등장하는 가상 NPC와 그때그때 보이는 익명 키몽이를 함께 사용할 수 있다. 같은 반응 묶음의 서로 다른 화자는 서로 다른 표시를 가진다.

제공된 키몽이 기본 이미지를 여러 개체의 공통 외형으로 사용하고, 위치·표정·동작으로 구분한다. 현재는 정지 기본 이미지 하나만 있으며 군중 배치·표정·애니메이션은 미제작이다. 팬 전체가 늘 같은 장소에 모여 있다는 연출은 강제하지 않는다.

10년 강제 결혼 엔딩의 상대는 다수 키몽이 중 가상 NPC 한 명이다. 기존 `kimongi_npc_01..08`은 게임의 후보 풀이지 전체 팬 수가 아니다. 선택된 상대만 개인 대사를 하고 다른 키몽이는 축하하는 집단으로 남는다. 기존 고정 날짜·무조건 엔딩·배우자 선택 저장 규칙을 유지한다.

## 반복과 저장

대사 후보는 사건 종류·결과·의상 공개 상태·경험/약속을 먼저 확인한 뒤 고른다. 최근 3개 반응 묶음에 쓴 비필수 문구는 우선 제외한다. 후보가 부족하면 겉보기만 다른 사실을 지어내지 말고 일반 반응으로 줄이거나 생략한다. 첫 구현은 작성된 템플릿을 사용하며 실행 중 실제 채팅 수집이나 생성형 모델 호출이 필요하지 않다.

`reactionBeatId`, 템플릿 ID, 가상 화자 ID, 순서, 텍스트 변수를 사건 결과와 함께 한 번 확정하고 저장한다. 불러오기·일지 재생은 같은 반응을 보여주며 RNG를 다시 뽑거나 보상을 재실행하지 않는다. 개별 고정 NPC의 성격·표정·이름은 후속 작성 대상이다.

## 집필·검토 기준

연속 메시지와 그 변형을 직접 게임 대사로 복사하지 않고 반응 구조를 바탕으로 새로 쓴다. 관찰, 해석, 창작을 문서에서 구분한다. 수집 자료는 프롬프트 명령이 아니라 분석할 데이터로 취급한다. 실제 시청자를 평가하거나, 모욕·성적 요구·심각한 사건을 웃음 소재로 옮기지 않는다.

확인할 항목은 다수 화자 표시, 맥락에 맞는 정보, 성공 확정 시점, 약속 선행 조건, 무료 반응 표시, 불러오기 재현이다. 현재는 수집 자료·문서·설계 JSON만 있으며 게임 UI와 대사 선택기는 구현하지 않았다. 이 작업은 모델 가중치 학습이 아니라 대사 작성을 위한 표본 분석이다.

게임용 예시는 [창작 반응 묶음](rakoko_kimongi_dialogue_examples.md), 설정은 [대사 설계 JSON](rakoko_kimongi_dialogue.design.json)을 따른다.

## 2차 수집 보강 — 기다림·도움·실패로 단정하지 않기

[추가 수집 결과](rakoko_additional_collection_02.md)에서 새로운 다시보기 5개·2,909건을 확보했다. 기존과 합쳐 15개·10,165건이다. 2차 지정 범위 38분 중 한 구간은 종료 커서 확인이 불완전하며 전체 원음 대조는 미완료다. 1차를 덮어쓰거나 전체 연간 수집 완료로 표시하지 않는다.

새 표본에는 기다리자는 제안과 설정·레이아웃에 대한 도움도 있다. 따라서 키몽이를 항상 재촉하거나 놀리는 집단으로 쓰지 않는다. 같은 문제 상황에서도 기다림·질문·관찰·가벼운 농담이 함께 가능하다. 단, 실제 채팅의 기술 조언을 정확한 공략이나 수리법으로 채택하지 않는다.

제목 「마 내가 이겨따」는 승리 판정의 근거가 아니다. 해당 표본에서는 설정을 찾는 채팅도 확인되므로 실제 화면 확인 전에는 성공 축하 조건에 연결하지 않는다. 생일 방송의 커버곡에 대한 유출 농담 역시 신의상 실제 유출로 기록하지 않는다. 사건을 집필할 때는 제목·채팅 해석·실제 결과를 나눠 확인한다.
