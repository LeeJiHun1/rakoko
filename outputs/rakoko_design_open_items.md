# 다음 설계·결정 사항 점검

2026-11-05 · 현재 파일 기준. 아래 권장안은 검토 제안이며 기존 규칙·수치를 자동 변경하지 않았다.


> 2026-11-05 최신 작업 범위: 방송·채팅 추가 수집은 사용자 지시로 중단했다. 이후 우선 작업은 게임 완성도이며 [완성도 조사](rakoko_game_quality_research.md)와 [검증 계획](rakoko_quality_validation_plan.md)을 따른다. 아래 원음/과거 채팅 보완 항목은 미완료 이력으로 보관하고 현재 조사 확대 대상으로 삼지 않는다.

## 1. 진행 속도와 날짜 도약 — 우선 설계

현재 일반 사건의 초·중·후반과 네 후반 보존 소재는 경과 날짜에 묶여 있다. 사용자가 생일·주년으로 빠르게 이동하면 방송 경험과 스테이터스가 적어도 후반 추첨으로 바뀐다. 반면 날짜 도약은 수치·경험·자금을 주지 않는다.

권장: 달력은 기념일·모듈 기한·엔딩 연수에 사용하고 일반 콘텐츠 진행 단계는 완료 방송 횟수와 주요 경험을 중심으로 판정한다. 실제 역사 날짜를 갖는 각색의 날짜 조건은 별도로 유지한다. 구간 수치는 최신 반복/장기 콘텐츠를 반영한 공급 검토 뒤 정한다.

취향 선택: 첫 일반 엔딩까지 목표 시간을 정해야 한다. [사례 조사](rakoko_playtime_comparison.md) 뒤 새 권장 검토안은 첫 일반 엔딩15~25분·익숙한 재플레이10~15분이며 긴 진행·엔딩 수집은 별도다. 이전45~60분 제안은 대체한다. 현재는 측정된 플레이타임이 없으므로 날짜를 빨리 넘길 수 있다는 사실만으로 달성을 보장하지 않는다. 처음1회 전체 UI 시연에서 선택 수·읽는 시간·반복 비중을 측정한다.

## 2. 모든 엔딩의 선행 경험 생산자 — 구현을 막는 빈칸

32개 EX 경험 중26개는 needs_content_binding, 6개는 design_binding_engine_pending이다. 6개도 엔진에서 실제 지급되는 상태는 아니다. 엔딩 조건표가 존재하는 것과 게임에서 그 조건을 얻을 수 있는 것은 다르다.

필요 산출물: 각 일반 결말마다 ‘초기 상태 → 선행 사건/결과 ID → 스테이터스 도달 → 현재 기획 준비 → 엔딩 사건 → 종결 선택’의 경로를 작성한다. 경험을 주는 효과·누락/실패/포기 시 재도전·관련 gameId/projectId·필수 NPC 역할을 명시한다. 어떤 도달 경로도 없는 결말은 구현 완료로 세지 않는다.

## 3. 성장·경제·반복을 합친 진행 모형 — 우선 검증

기본 준비/코너 성장은 있지만 기존 일반312선택의 사건 결과 성장 보너스가 미배정이다. 인지도는 새 family 완료의 영향이 커서 반복 기획만 하는 플레이가 수익 규모를 올릴 수 있는지 확인해야 한다. 운영력65·게임 숙련도60 같은 선택이 언제 열리는지도 전체 경로로 검증하지 않았다.

권장: 선택의 실제 결과에 맞춰 성장·손익·경험을 먼저 연결하고, 잡담/게임/팬 기획/장기 서버 중심 경로를 비교한다. 규모 해금까지 방송 수, 소액과 대형 기획의 구매 시점, 자금 부족으로 포기하는 비율, 반복 소재 빈도, 최초 일반 엔딩 시점을 함께 측정한다. 단순히 전체 수입과 가격을 같은 비율로 올려 재미를 판정하지 않는다.

현 경제 검토는 고정 스테이터스의 저축 비교다. 실제52회 플레이나 모든 선택을 반영한 시뮬레이션으로 대체 해석하지 않는다.

## 4. 결제 후 작업·취소·참가 기한 — 우선 설계

결제 전 잔액 부족은 포기로 확정되어 있다. 결제한 뒤에는 구매 영수증·납품 대기가 있으므로 별도 규칙이 필요하다. 현재 주요 외주는 다음 참여 방송, 큰 기획은3~4회 뒤 납품하는 기본값이고 장기 콘텐츠는120일 참가 창을 사용한다.

남은 판정: 미착수 주문 취소, 납품 후 수정, 날짜 도약으로 기획 기한을 넘긴 경우, 유출 조기 공개로 남은 의뢰가 필요 없어진 경우, 정상/강제 엔딩 때 진행 중 의뢰의 보관과 환급 여부.

권장: 미착수 용역 취소는 전액 환급, 착수 뒤에는 사전에 표시한 완료분만 비용 확정하는 정책을 검토한다. 이미 적용한 의상 준비 행동의 비용은 기존 비환급·진행 보존 규칙을 유지한다. 장비를 샀다는 이유로 모든 운영 능력이나 경험을 자동 충족시키지 않는다. 환급도 원 결제 참조·중복 방지가 필요하다. 이 제안은 아직 경제 원본에 적용하지 않았다.

## 5. 등장인물과 실제 화면에 보일 대사 — 제작 결정

현재 기본 라코코·키몽이·의상4종 정지 이미지는 있다. 하지만 장기 서버의 주최자/팀원/시민, 강제 엔딩의 키몽이 NPC8개 ID에 대응하는 인물 설정·대사·표정은 구체화해야 한다. 엔딩 결과·후일담의 짧은 요약을 실제 마지막 사건의 대사와 연출로 옮기는 작업도 남아 있다.

권장 기본안: 라코코·키몽이 중심으로 만들고 함께 방송하는 역할은 독자 NPC로 구성한다. 실제 동료 스트리머를 이름·외형·고정 성격을 가진 등장인물로 넣을지는 사용자 취향 결정으로 남긴다. 원음·발화자 검증이 없는 대사는 실제 인용으로 표시하지 않는다.

## 6. 조작 화면과 기술 선택 — 첫 시연에서 결정

현재 실행 앱의 package.json·src·index.html은 없다. 프레임워크·배포 서비스·최종 픽셀 격자도 미확정이다. 이들은 구현 담당자가 선택할 수 있어 추가 사용자 승인을 기다릴 사안은 아니다.

첫 시연은 준비/편성 → 사건의 잠긴 선택과 이유 → 자금 지출/포기 → 약속/모듈 → 일지/다음 날짜 → 저장 재개를 연결한다. 그 뒤 의상 유출과 일반 엔딩1경로·강제10년 예외를 테스트 장면으로 붙인다. 이는 검증용 구현 순서이며 출시 엔딩33종이나 콘텐츠 범위를 줄이는 결정이 아니다.

UI에서 확인할 것: PC/모바일 가독성, 자산·능력·서버 자원 구분, 기념일/엔딩 가능일 이동, 마지막 기획 승인·예약, 다른 게임 숙련도를 혼동하지 않는 표시, 반복 대사 빠르게 읽기, 설정/일지/환복에 행동이 들지 않는지.
