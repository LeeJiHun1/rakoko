# 〈라코코의 방송일지〉 게임 완성도 조사

2026-11-05 · v1.0 · 조사 결과와 프로젝트 적용 제안

방송·채팅 추가 수집은 사용자 지시에 따라 중단했다. 이번 조사의 대상은 플레이 가능한 연결, 선택의 납득 가능성, 반복의 변화, 진행 속도, 저장 안정성, 화면·음향·접근성이다. 다른 팬게임 비교 조사를 재개하지 않았다.

**우선순위는 성장·경험·엔딩 연결 → 한 판 속도 검증 → 반복과 일지의 후속 회수 → 화면·음향 마감이다.** 연구 자료가 있어도 실제 게임 동작을 확인하기 전에는 완성으로 세지 않는다. 현재 실행 앱은 없고, 이번 작업은 구현에 쓸 조사·정적 점검·검증 계획이다.

## 1. 현재 설계에서 먼저 해결할 문제

[정적 점검](rakoko_quality_gap_audit.md)과 [결말별 연결표](rakoko_quality_gap_audit.json)를 현재 데이터로 생성했다.

|확인한 사실|플레이에 미치는 영향|우선 조치|
|---|---|---|
|EX32종 중26종 생산 사건 미연결, 6종 설계 연결/엔진 대기|조건표에 있는 엔딩을 실제 플레이로 얻는지 확인할 수 없음|일반32결말마다 새 게임부터 종결 선택까지 재현 경로 작성|
|일반 선택312개의 추가 성장 효과 미배정|실제 효과와 조건이 연결된 성장 속도·수익 규모를 계산하기 어려움|결과에 맞는 효과와 경험 생산자를 연결하고 대표 진행을 계산|
|55개 참조에 변주1개, 목표3개|재등장은 허용돼도 같은 문구·진행이 반복될 수 있음|기존 결과·현재 기획을 반영한 추가110변주 집필. 단순 말바꾸기로 채우지 않음|
|일반 콘텐츠 단계가 경과 날짜에 의존|생일·주년으로 이동했을 때 초보도 후반 사건 비중으로 바뀔 수 있음|달력과 완료 방송/경험 중심 콘텐츠 단계를 나누는 안을 검증|
|납품·취소·기한 만료의 일부 정책 미완성|선결제한 기획이 날짜 이동이나 엔딩에서 불분명해짐|결제 전 포기와 결제 후 주문 상태를 구분해 정의|
|표시 PNG8개 합계10.13MiB|전부 선로딩하면 첫 화면과 메모리에 부담 가능|현재 의상·배경을 우선 로드하고 나머지는 필요할 때 로드|

성장 효과 미배정은 기본 성장이나 원문 선택의 모든 효과가 없다는 뜻이 아니다. 변주 참조55개는 독립 실화55건이 아니다. 10.13MiB는 파일 용량이며 실제 네트워크·메모리 성능을 측정한 값이 아니다.

강제 엔딩은 독립 파일과 경로 목록에 복사본이 있다. 핵심 날짜·확률은 같지만 버전과 다수 키몽이 설명 필드가 다르다. 정본을 하나로 두고 동기화 검사를 붙일 대상이다. 이번 조사에서는 원래 규칙을 바꾸지 않았다.

## 2. 조사에서 가져올 핵심 원리

### 맥락이 맞는 사건을 먼저 고르고 그 안에서 변화를 만든다

서사 설계자 Emily Short는 짧은 사건을 내용·전제·상태 효과의 단위로 설명한다. Yarn Spinner 공식 문서는 조건 필터링과 맥락 적합성·최근 노출 이력을 함께 고려하는 선정 전략을 설명한다. [QS-01](https://emshort.blog/2019/11/29/storylets-you-want-them/), [QS-02](https://docs.yarnspinner.dev/3.1/write-yarn-scripts/advanced-scripting/storylets-and-saliency-a-primer)

프로젝트 적용 제안: 강제10년 종료와 확정 일정·후속 처리의 기존 우선순위를 유지하고, 적격 일반 사건 안에서만 가중치와 최근 이력을 적용한다. 낮은 가중치는 조건 미달을 허용하는 장치가 아니다. 팬에게 공개하지 않은 의상, 하지 않은 약속, 참가하지 않은 대회의 후속은 뽑지 않는다.

반복 사건의 변주는 `같은 문제의 재발`뿐 아니라 `지난 해결책을 사용함`, `이번에는 준비해 둠`, `다른 기획이라 다른 제약이 생김`으로 작성한다. 이전 선택을 기억하는 한 문장과 실제 상태 차이를 함께 두면 방송일지의 정체성이 살아난다. 재등장한 사실만으로 최초 인지도 보상을 또 주지 않는다.

### 선택 전에 의도·비용·조건을 알 수 있게 한다

Choice of Games의 집필 지침은 플레이어가 선택의 의도, 예상 결과, 관련 능력과 어려움을 이해할 수 있어야 한다고 설명한다. [QS-03](https://www.choiceofgames.com/2016/12/how-to-write-intentional-choices/)

프로젝트 적용 제안: 선택마다 행동의 목적, 비용/관련 능력, 결과의 범위를 붙인다. 잠긴 선택에는 현재/필요 수치와 부족한 경험을 표시한다. 실패 가능성이 있는 곳은 기존 방침대로 판정 전 확률·위험을 알린다. 감정적 대사의 결말까지 모두 설명할 필요는 없다.

창작 예시 — 자료 화면이 안 뜨는 사건:

|표시할 선택|플레이어가 알아야 할 차이|결과에서 확인할 것|
|---|---|---|
|연결을 점검한다|지금 문제를 조사함|복구/미해결 상태와 다음 행동|
|대체 화면으로 이어간다|관련 운영 조건, 준비한 대체 자료가 필요한지|대체 진행의 실제 완료 범위|
|잡담으로 전환한다|현재 기획은 보류됨|준비 기획이 자동 완료되지 않으며 후속 메모가 남음|

이 표는 대사·효과 계약의 작성 예시다. 기존 선택 효과를 구현했다는 뜻은 아니다. 모든 선택에 손해를 억지로 추가할 필요는 없지만, 문구만 다른 선택을 전략적 차이라고 포장하지 않는다. 유료 사건은 잔액 부족 시 포기하는 기존 규칙을 유지한다.

### 결말은 지난 선택의 회수 장면이어야 한다

Choice of Games의 결말 설계 글은 여러 목표와 마지막 분기가 앞선 선택의 의미를 남기도록 구성하는 방법을 제안한다. [QS-04](https://www.choiceofgames.com/2016/11/end-game-and-victory-design/)

프로젝트 적용 제안: 각 결말의 마지막 사건에 실제로 경험한 도전·키몽이와의 약속·선택한 방송 운영 방식 중 해당하는 기록을 회수한다. 같은 축하 화면에서 제목만 바꾸지 않는다. 엔딩을 위한 마지막 종결 선택과 일반 업적을 구분한다. 수치·경험·현재 기획 조건, 일반32결말과 강제1결말은 유지한다.

미도달 결말의 자세한 내용을 새 게임부터 전부 공개하지 않는다. 현재 플레이에서 수락한 기획의 다음 준비 항목은 확인할 수 있게 한다. “무엇을 해야 할지 모르겠다”는 막힘을 해소하되 기존 미도달 엔딩 스포일러 제한을 지킨다.

## 3. 한 판 속도와 피드백

아래 수치는 문헌의 업계 평균이 아니라 **프로젝트에서 검증할 제안값**이다. 기존 첫 일반 엔딩15~25분·재플레이10~15분 역시 실측·사용자 확정값이 아니다. 모든 고난도 결말을 같은 시간에 보장하지 않는다.

|항목|첫 시연 제안|측정 방법|
|---|---|---|
|첫 방송 완료|설명 포함3분 안팎을 우선 점검|읽기·준비/편성·결과/일지 시간을 분리 기록|
|보통 사건 길이|상황1~3문장, 반응은 기존 기본3줄|선택의 이해와 관계 없는 반복 문장을 줄임|
|익숙한 준비·편성|이전 설정 재사용을 제안|재사용해도 실제 준비 행동·비용·조건을 다시 검증|
|이미 읽은 연출|즉시 표시·건너뛰기 허용|보상·RNG·경험이 재실행되지 않는지 확인|
|선택의 즉시 피드백|관련 상태 변화와 짧은 이유를 표시|수치 전체를 매번 나열하지 않고 바뀐 항목을 확인|
|후속의 인지|일지·준비 화면에서 남은 약속/기획을 표시|대표 장면으로 고르지 않아도 후속이 사라지지 않음|

첫 화면에서 모든 시스템을 설명하지 않는다. 첫 준비에서 한 번, 잠긴 선택을 만났을 때 한 번처럼 필요한 위치에 짧게 안내한다. 튜토리얼 때문에 행동·코너 수를 별도로 늘리지 않는다. 정보·설정·일지·환복 열기는 기존대로 행동을 소모하지 않는다.

날짜 이동을 빠르게 해도 성장·수입·참여 경험이 자동 증가하지 않는다. 생일·주년 예약과 만10년 무엔딩 종료는 미리 보여주며, 날짜 도약으로 그 판정을 건너뛰지 않는다. 플레이 시간을 맞추기 위해 필수 경험을 삭제하거나 임의의20분 종료 타이머를 넣지 않는다.

## 4. 저장과 재개를 게임의 일부로 검증

IndexedDB는 여러 상태 변경을 하나의 트랜잭션으로 다룰 수 있다. Chrome의 페이지 수명주기 안내는 특히 모바일에서 종료 이벤트에 저장을 맡기면 안 된다는 점을 설명한다. MDN은 브라우저 저장의 출처별 관리·용량 실패·제거 가능성을 정리한다. [QS-07](https://web.dev/articles/indexeddb), [QS-08](https://developer.chrome.com/docs/web-platform/page-lifecycle-api), [QS-09](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

적용 제안은 기존 원자 저장 설계를 구체적으로 검증하는 것이다. 선택 결과·난수·비용·경험·명령 ID가 함께 커밋된 뒤 성공 화면을 표시한다. 저장 실패면 마지막 성공 상태를 보존하고 같은 명령을 재시도한다. 두 탭의 오래된 revision 쓰기, 모바일 강제 종료, 이전/다음 탐색, 저장 파일 버전 변경을 별도로 시험한다.

일지 내보내기/가져오기를 제공한다. 브라우저 저장과 같은 출처의 복사본은 출처 데이터 전체가 제거되는 상황의 별도 백업이 아니다. 영구 저장 요청 승인도 사용자 삭제까지 막는 보장은 아니다. 설정 화면에 상태를 알리고 플레이 도중 반복 경고를 띄우지 않는다.

ink 공식 문서는 서사 상태의 저장·복원과 게임 연동, 태그 기반 표시 정보를 설명한다. 이를 참고해 공개 연출·표정·효과음의 재생과 보상 커밋을 분리한다. [QS-06](https://github.com/inkle/ink/blob/master/Documentation/RunningYourInk.md)

## 5. 읽기·터치·키보드·성능

|조사 근거|프로젝트 적용 제안|주의|
|---|---|---|
|[W3C 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)|본문과 조건 설명4.5:1, 큰 텍스트3:1 기준으로 점검|비활성 버튼에는 예외가 있지만 잠금 이유까지 흐리게 만들지 않음|
|[W3C 목표 크기](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)|주요 선택 버튼 높이44 CSS px 이상을 제작 목표로 사용|해당 AA 항목의 원칙적 최소는24×24px이며 예외/간격 규정이 있음|
|[W3C 재배치](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)|320 CSS px 폭에서 대사·선택·조건을 한 열로 표시|텍스트 UI를 통째로 게임의2차원 예외에 기대지 않음|
|[W3C 키보드](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)|키보드만으로 모든 기본 흐름, 잠금 이유도 접근 가능|마우스 호버만으로 필수 정보를 제공하지 않음|
|[Microsoft 텍스트 표시](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101)|본문 확대200%, 읽기 쉬운 한글 대체 글꼴|가이드의 물리 픽셀 수치를 웹 CSS px로 그대로 복사하지 않음|
|[Web Vitals](https://web.dev/articles/vitals)|LCP≤2.5초, INP≤200ms, CLS≤0.1을 목표로 측정|실사용75백분위 기준. 개발 PC 한 번 측정으로 달성 선언하지 않음|

캐릭터·배경의 표시 공간을 먼저 확보해 선택지가 로딩 중 움직이지 않게 한다. 처음에는 현재 의상과 필요한 배경만 우선 로드한다. 이미지 실패 시 기존 대체 이름·재시도·계속 진행을 유지한다. 음소거·동작 줄이기 상태에서도 잠금·성공·실패·새 약속의 정보가 전달되어야 한다.

후보 파일은 `work/rakoko/quality_sources/vendor_candidates/`에 두었다. 시스템에 글꼴을 설치하거나 게임에 연결하지 않았다. 폰트를 포함해 배포할 때는 확보한 저작권 고지와 라이선스를 함께 관리한다. 외부 효과음은 플랫폼 후원 알림음을 흉내 내는 용도로 쓰지 않는다.

음향 마감 제안: 버튼 반응, 선택 확정, 잠금/부족, 새 기록, 의상 공개의 역할을 구분하되 키몽이 채팅 한 줄마다 소리를 내지 않는다. BGM/SFX 음량·음소거와 동작 줄이기를 제공하고 중요한 결과는 텍스트·표시로도 전달한다. 실제 음원 후보의 청취 검수는 남아 있다.

## 7. 실제 개발에 연결할 순서

1. 대표 사건의 의도·효과·경험·후속·일지까지 한 경로를 연결한다. 일반 엔딩 하나와 무엔딩10년 예외를 검증용으로 연결하되 출시33결말 범위를 줄이지 않는다.
2. 일반32결말의 선행 경험 생산자를 채우고 각 결말의 경로 증명을 만든다. 높은 능력만 주입해 엔딩 화면을 여는 테스트로 대체하지 않는다.
3. 잡담·게임·팬 기획·장기 콘텐츠 중심 진행에서 성장·수입·지출·반복을 함께 측정한다. 달력과 콘텐츠 진행 단계 분리안을 이 결과로 정한다.
4. 주문 납품·취소·날짜 도약·정상/강제 엔딩의 거래 상태를 확정한다. 의상 준비의 기존 비환급·진행 보존은 유지한다.
5. 전후가 연결된 변주와 일지 회수를 쓰고, PC/모바일 화면·한글 글꼴·알파 경계·UI음을 마감한다.

[검증 계획](rakoko_quality_validation_plan.md)의 시나리오는 아직 실행하지 않았다. 조사18자료와 정적 검사가 게임 완성을 보증하지 않는다. 다만 다음 단계에서 무엇을 구현하고 어떻게 확인할지 바로 참조할 수 있다.

출처별 읽은 범위·적용 해석·접근 실패는 `work/rakoko/quality_sources/sources.json`에 보관한다. source 원문 사실과 프로젝트 제안을 구분했으며 외부 엔진·프레임워크의 채택은 결정하지 않았다.
