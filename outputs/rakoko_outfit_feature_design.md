# 신의상 준비·공개·환복 기능 설계

2026-11-04 · 사용자 확정사항 반영 v1. 기능 설계이며 실행 코드 구현 완료를 뜻하지 않는다.

## 통합 검토 반영 v1.1

이 문서의 사용자 확정사항은 유지한다. 아래의 구체화는 `rakoko_game_feature_spec.md`와 함께 적용하며 이전의 모호한 설명보다 우선한다.

- 유출 미발생 검사도 `방송 ID + 의상 ID`로 저장한다. 방송당 첫 적격 일반 코너에서 한 번만 검사하고 공개 슬롯에서는 검사하지 않는다. 일부 유출이 한번 발생한 의상은 재유출하지 않는다.
- 준비 행동당 +25, 행동 총 4회는 조정 가능한 초깃값이다. 준비 의상 변경은 일시 중단이며 진행도·유출 기록을 유지한다. 취소해도 소비 행동은 환급하지 않는다.
- 의상 공개는 해금과 시연만 수행한다. 착용은 ‘지금 입기’ 선택으로 따로 적용한다. 연출 종료 후 이전 의상을 유지할 수 있다.
- 정식 공개는 예약 코너 1칸을 차지한다. 조기 공개 시 같은 슬롯을 소개/팬 참여 코너로 교체하며 추가 공개 보상을 주지 않는다.
- 처리 순서는 선택 결과·해금·예약 교체·일지·명령 ID의 원자 저장 후 연출이다. 저장 실패하면 완료로 표시하지 않는다. 조기 공개 대응에 별도 비용은 없다.
- 세이브에 `lastLeakCheckBroadcastId`, `leakHasOccurred`, `processedCommandIds`, `pendingPresentation`을 포함한다. pendingPresentation은 보상과 분리된 재생 정보이며 건너뛰어도 결과는 유지한다.
- 단일 세이브의 다중 탭 충돌·구버전 이관·이미지 로드 실패 대응은 통합 명세를 따른다.

## 확정한 경험

유령·메이드·경찰복·수녀복을 각각 준비하고 공개한다. 공개 이후에는 방송 준비 화면과 방송 중 모두 무료로 자유롭게 환복할 수 있다. 일부 유출이 발생하면 플레이어가 대응을 선택하고, 그 결과에 따라 예정일보다 빠르게 전체 공개될 수 있다. 유출은 가상 게임 사건이며 실제 라코코에게 일어났다는 기록으로 표시하지 않는다.

기본 의상은 시작부터 해금한다. 의상마다 상태를 따로 저장하고, 플레이어가 공개한 순서가 달라도 작동한다. 방송일지 창작 의상은 이번 이벤트 목록에서 제외한다.

## 상태와 해금 규칙

|상태|가능한 행동|환복 가능 여부|
|---|---|---|
|미착수|준비 시작|불가|
|준비 중|제작 진행·점검·공개 예약·유출 대응|불가|
|일부 유출|유출 대응 선택|불가. 일부 유출만으로 전체 해금하지 않음|
|공개 완료|일지 기록·공개 후 코너·환복|가능|

유출은 준비 상태에 붙는 별도 정보로 관리한다. 준비도, 예약일, 일부 유출 여부, 대응 결과를 분리해서 저장한다. 일부 유출을 수습하면 준비 중으로 돌아가되 유출 기록은 남는다. 전체 공개가 성립하면 공식 공개·조기 공개 모두 동일하게 해금된다. 같은 일지에서는 1주년 회고 뒤에도 해금, 현재 착용, 준비 진행도와 예약을 보존한다. 별도의 새 게임만 기본복에서 시작한다.

공개 중 연출은 일시적 화면 단계다. 공개 완료를 저장한 뒤 연출하므로 앱을 종료해도 다시 공개하거나 보상을 중복 지급하지 않는다. 연출은 건너뛰거나 이전 장면을 다시 볼 수 있고, 재감상은 이벤트를 재실행하지 않는다.

## 준비 흐름

1. 준비 목록에서 의상을 선택한다. 시작 단계에서는 이름·공개 전용 아이콘만 보여주고 완성 이미지는 숨긴다.
2. 제작 진행으로 준비도를 쌓는다. 이번 설계는 준비도 0~100을 사용하며 실제 비용·제작 기간을 재현하지 않는다.
3. 화면 점검을 하면 단기적으로 유출 위험이 낮아진다. 준비 진행과 점검은 기존 방송 준비 행동에 연결하며 확정되지 않은 재화 체계를 새로 강제하지 않는다.
4. 준비도 100이면 정식 공개를 예약할 수 있다. 날짜를 지났다고 자동 실패시키지 않고 다음 방송으로 미룰 수 있다.
5. 공개 전에는 확인 버튼으로 전체 그림을 미리 보여주지 않는다. 의상 선택 UI의 작은 썸네일도 잠금 상태로 유지한다.

초기 구현은 한 번에 준비하는 의상 1종으로 단순화하되, 완료된 의상들은 모두 보관한다. 동시 제작 수는 설정으로 확장할 수 있게 한다. 이 제한은 구현 초안이며 사용자 확정 요구사항은 아니다.

## 돌발 유출 사건

게임 속 실수 소재는 ‘방송 장면 전환에 미리보기 일부가 잡힘’, ‘예약 썸네일에 소매가 보임’, ‘의상 선택 창에 액세서리가 잠깐 노출됨’ 등이다. 해킹·사생활 유출·도난·실제 제작자 과실 묘사로 확장하지 않는다.

발생 조건: 준비 중이며 공개 전용 미리보기 단계에 도달한 의상. 초기 초안은 준비도 40 이상을 사용한다. 완성 원화 전체를 유출 카드에 표시하지 않고, 의도한 소품·색상만 별도 실루엣/아이콘으로 보여준다.

|대응|결과|
|---|---|
|화면을 바꾸고 예정대로 준비|전체 해금 없이 준비 재개. 이후 방송에서 가벼운 후속 대사 가능|
|티저였다고 받아친다|일부 공개 기록을 남기고 준비 재개. 정식 공개 도입 대사가 바뀜|
|그냥 지금 공개한다|조기 전체 공개 확정. 준비가 덜 된 경우 가벼운 미완성 연출을 기록하고 의상은 정상 해금|
|화면부터 확인하며 수습한다|확률 판정으로 수습 성공 또는 전체 미리보기 전환 실수→조기 전체 공개. 판정 전 실패 가능성을 UI에 알림|

유저가 위험 없는 대응도 선택할 수 있도록 한다. 무작위 조기 공개 경로도 유지하되, 일부 유출이 발생했다는 이유만으로 무조건 전체 공개시키지 않는다. 미완성은 설정·연출 준비 부족이며 깨진 캐릭터 그림을 보여준다는 뜻이 아니다.

### 확률 초깃값 — 조정 가능한 제안

- 방송 1회당 적격 시점에 유출 검사 1회. 기본 발생 확률 8%.
- 해당 방송에 화면 점검 완료 시 3%. 준비도 40 미만은 0%.
- 의상별 일부 유출 사건은 최대 1회. 같은 준비 건에서 무한 반복하지 않음.
- ‘확인하며 수습’ 선택의 실패 확률 25%, 해당 방송 점검 완료 시 10%.
- 위 값은 실제 방송의 빈도 통계가 아닌 게임 밸런스 초깃값이다. UI 문구와 실제 판정은 같은 설정값을 참조한다.
- 판정 시 게임 난수 상태와 결과를 저장한다. 새로고침·저장 불러오기로 동일 사건이 다시 추첨되지 않게 한다.

따라서 점검하지 않은 적격 방송에서 이 대응을 골랐을 때 유출→실수 전체 공개의 결합 확률은 8%×25%=2%다. 대응 선택 비율을 모르는 상태에서 모든 방송의 조기 공개율이 2%라고 표현하지 않는다.

## 정식 공개와 조기 공개의 차이

|항목|정식 공개|조기 공개|
|---|---|---|
|의상 해금|영구 해금|동일하게 영구 해금|
|기록|준비해서 공개한 장면|유출에 대응하다 먼저 공개한 장면|
|예정 코너|공개 코너 진행|‘이미 본 의상 다시 소개하기’, 의상 이름 투표·디테일 소개 중 하나로 전환|
|남은 준비|완료|불필요한 공개 준비 취소. 남은 작업을 선택형 보완 코너로 바꿈|
|후속 사건|첫 착용 방송·기념 기록|급하게 공개한 해프닝 회수·못 보여준 디테일 소개|

정식 공개를 못 했다는 이유로 의상 성능이나 해금 범위를 깎지 않는다. 공개 방식의 차이는 코너·일지·후속 이야기로 남긴다. 이전 예약 이벤트는 동일 ID로 대체하여 중복 공개를 막는다.

## 공개 후 자유 환복

준비 화면에는 ‘의상’ 버튼, 방송 중에는 화면을 크게 가리지 않는 ‘환복’ 버튼을 둔다. 현재 의상과 해금된 의상을 보여주고 선택 즉시 적용한다. 무료이며 준비 포인트·행동 횟수·방송 시간을 소모하지 않는다. 선택한 의상은 다음 방송에도 유지한다.

미공개 의상은 잠금 상태이며 선택해도 착용하지 않는다. 공개 시연에 필요한 캐릭터는 이벤트 전용 임시 표시로 처리하고, 환복 권한은 해금 정보로 검사한다. 연출 재생 중에는 교체 요청을 잠시 대기시키고 종료/건너뛰기 직후 적용한다.

환복으로 능력치·시청자 수·후원 보상을 반복 획득하지 않는다. 옷을 갈아입는 것과 새 의상 공개를 별개 행동으로 처리한다. 게임·합방 코너에도 선택한 옷을 유지하며, 고정 컷이 있는 경우 사용할 그림이 없다고 다른 옷으로 조용히 바꾸지 않는다. 초기는 공통 전신을 재사용한다.

## 데이터와 기능 경계

|데이터|역할|
|---|---|
|outfitId|base / ghost / maid / police / nun|
|status|locked / preparing / revealed|
|preparationProgress|0~100|
|plannedRevealBroadcastId|공개 예정 방송. 없으면 null|
|leak|발생 방송·발생 종류·선택·판정 결과·해결 여부|
|reveal|실제 공개 방송·planned/early_manual/early_accident·중복 처리 방지 ID|
|equippedOutfitId|현재 착용. 공개 정보와 별도 저장|
|journalEntryIds|공개·후속 기록 연결|
|rngState|재추첨 방지 난수 상태|

기능은 `startPreparation`, `advancePreparation`, `scheduleReveal`, `checkLeak`, `resolveLeak`, `completeReveal`, `equipOutfit`으로 나눈다. 유출 대응과 공개 완료는 저장 단위 하나로 처리한다. `equipOutfit`은 해금 검증 후 외형만 바꾸며 공개 보상을 호출하지 않는다. 서버가 없는 로컬 게임이라면 저장 데이터와 이벤트 처리로 구현 가능하다.

## 필요한 비주얼 연결

- 의상 전신 4종: `assets/events/outfit-reveals/manifest.json`의 ID 사용.
- 기본 전신: `assets/characters/rakoko-base-v1.png`.
- 공개 전후 배경: 기존 닫힌/열린 커튼 사용. 크로스페이드 연출.
- 유출 전용 카드: 전체 원화 대신 소매·모자·색상 단서 등 별도 이미지 필요. 아직 미제작.
- 의상별 해금 썸네일·선택 표시·잠금 UI: 필요. 기존 방송일지 의상 아이콘을 네 의상 공용 아이콘으로 오인하지 않음.
- 네 의상의 표정별 초상은 아직 없음. 초기에는 전신과 대화 텍스트로 진행할 수 있음.

## 구현 시 확인할 시나리오

1. 기본 의상만 시작 시 착용 가능하고 미공개 의상 선택은 거절된다.
2. 정상 공개 후 준비·방송 중 무료 환복이 가능하고 다음 방송에도 유지된다.
3. 일부 유출만으로는 의상이 해금되지 않는다.
4. 수습·티저 대응 후에도 준비도와 예정 공개가 유지된다.
5. 수동/실수 조기 공개는 한번만 해금하고 기존 예약을 후속 코너로 바꾼다.
6. 공개 완료 직후 종료·불러오기·연출 재감상으로 보상이 중복되지 않는다.
7. 유출이 같은 의상에서 재발하지 않고 새로고침으로 판정이 바뀌지 않는다.
8. 유령→메이드→수녀→경찰 등 순서가 달라도 다른 의상의 준비·착용 상태가 손상되지 않는다.
9. 환복 반복은 성장 수치·재화·시청자 보상을 만들지 않는다.

## 추가 질문 상태

사용자 답변으로 일부 유출 후 대응 선택, 준비·방송 중 무료 환복을 확정했다. 구현 착수 전에 반드시 답해야 할 추가 질문은 현재 없다. 확률 수치·준비 소요량·동시 제작 수는 설정 가능한 초깃값으로 두고 플레이 검토 후 조정한다.


## 2026-11-05 방송 자금 통합

기본 준비 행동은500,000원과 행동1회를 함께 사용해+25로 한다. 잔액이 부족하면 행동을 선택할 수 없고 이번 준비를 건너뛰며, 돈/행동/진행도 중 일부만 적용하지 않는다. 이미 지불한 진행은 대상 변경·중단·포기에도 보존하고 환급하지 않는다. 유출 조기 공개는 남은 미래 준비비를 없애지만 과거 비용을 돌려주지 않는다. 추가 공개비와 해금 후 환복은0원이다. 설정은 rules.design.json이 참조하는 rakoko_economy.design.json을 따른다.
