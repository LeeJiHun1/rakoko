# 장기 콘텐츠·서버·대회 통합 설계

2026-11-05 · v1.0. 방송 안의 사건이 이어지는 장기 콘텐츠를 추가한다. [조사](rakoko_long_content_research.md), [사건64종](rakoko_long_content_events.md), [JSON](rakoko_long_content.design.json)을 구현 입력으로 사용한다. 현재는 설계 데이터이며 실제 게임 실행·온라인 서버 접속 기능이 아니다.

실제 사례 이름은 조사 문서에 보관한다. 게임의 서버명·주최자·팀·시민·대진·지도·결과는 독자 설정을 쓴다. 라코코가 해당 실제 서버나 대회에 참가했다고 표시하지 않는다. 도시 역할은 게임 플레이 중의 임시 역할이며 방송 주인공은 계속 라코코다. 가벼운 직업·서비스·행사 중심으로 작성하고 오컬트·심각한 분쟁·사생활 사건은 넣지 않는다.

플랫폼 주최와 스트리머 주최를 구분한다. 플랫폼 대회는 신청·자격 확인·공식 규정·시점 송출·대진을 강조한다. 스트리머 친선전은 초대·자체 규칙·팀 균형·스크림·참가자 교류를 강조한다. 조직 주최 CR CUP을 개인 단독 주최 사례로 잘못 분류하지 않는다.

## 참가와 방송 편성

초기에는 장기 콘텐츠를 동시에 1개 활성화한다. 초대 목록은 보관하고 거절·나중에 참가를 무료로 제공한다. 참가와 역할 선택은 플레이어가 정한다. 낮은 인지도 때문에 모든 콘텐츠를 막지 않도록 공개 연습·교육·지원 역할을 둔다. 본선 출전 자격과 연습 참가 자격은 서로 다르다.

선택한 콘텐츠는 방송 3칸 중 G 또는 S 한 칸에 직접 편성한다. 추가로 반복 장면을 한 칸 더 넣을 수 있어 방송당 최대 2칸이다. 슬롯을 무한히 추가하지 않는다. 준비 행동은 기존 2회를 공유한다. 본선·공개 같은 고정 장면은 예약 시 칸을 확보하고, 기존 의상 공개·수락한 기념일을 덮어쓰지 않는다.

일반 우선순위는 강제10년 엔딩 → 미해결 선택 재개 → 해당 칸 예약 → 적격 후속 → 플레이어가 편성한 장기 콘텐츠 → 일반 추첨 → 일상이다. 겹친 후속은 대기열로 보존한다. 장기 콘텐츠는 사용자가 편성한 기획이므로 일반 출처90/10 등의 무작위 배분 대상이 아니다.

## 단계와 반복

`invited → orientation → working → project_ready → rehearsed → closed`를 사용한다. 각 모듈은 진행5사건과 작업 단계의 반복3사건, 합계8개다. 한 방송에서 단계 전이는 최대1번이다. 진행 사건은 그 모듈 인스턴스/단계에서 한 번만 적용하고 다음 단계 사건은 다음 참여 방송부터 가능하다. 따라서 최소5개 참여 방송에 걸친다.

반복 사건은 같은 모듈의 참여 방송 간격2회 이상, 한 방송 최대1개다. 다른 방송을 켠 것만으로 모듈 참여 간격이 진행되지 않는다. 진행 사건에 일반 조우의 ‘같은 group 이후2회 제외’를 적용하면 단계가 불필요하게 막히므로 장기 모듈의 진행·반복·고정·필수 후속에는 적용하지 않는다. 대신 단계 전이1회·같은 사건1회·최대2칸 제한을 지킨다.

재참가하면 새로운 moduleInstanceId와 seasonId를 만든다. 거점·서버 신뢰·역할·물자는 새 시즌의 지역 상태로 초기화한다. 전역 스테이터스·해당 게임 숙련도·원 사건이 연결된 경험·옷장·완료 일지는 유지한다. 같은 원 인스턴스 재개로 보상이나 경험을 다시 얻지 않는다. 반복 본문의 세부 원인·자원·손님·작업 구역 변주는 추가 제작한다.

## 스테이터스와 선택 잠금

모든 선택은 문구를 표시하되 실제 조건이 부족하면 비활성화한다. ‘대회 팀 전술’은 해당 게임 숙련도, ‘공식 송출 점검’은 운영력, ‘축제 부스’는 기획력, ‘참여자 안내’는 단골층을 요구한다. 단순 설명 듣기·초보 교육·작은 역할 선택은 제한 없이 남긴다. 게임 숙련도는 모듈의 실제 gameId에 바인딩한다. 서로 다른 시즌이라도 같은 게임이면 숙련도는 유지되지만, 플랫폼 대회와 스트리머 대회의 게임이 다르면 공유하지 않는다.

선택의 전역 수치 보상은 기존 방송당+6 한도 안에서만 계산한다. 지역 수치 변화는 전역 수치를 대체하지 않는다. 지역 값은0~100으로 보존하고 서버 생활 자원도 가상 자원 지표다. 실제 현금·후원금·수익·빚으로 변환하지 않는다. 제출·참가·시점 송출 허가는 가상의 콘텐츠 안에서 확인된 플래그로 다루며 실제 게임사 허가가 확보됐다고 표시하지 않는다.

## 본선·승패·공략 결과

선수 본선은 실제 참가 확정 플래그가 있어야 선택할 수 있다. 공개 연습·진행 보조로 참가한 플레이어를 본선 선수나 우승자로 기록하지 않는다. 공식 개인 시점은 모듈 안에서 해당 역할의 허용 범위를 확인한 경우에만 진행한다.

게임용 기본 대회는 가상4팀 결선의2경기를 추상화한다. 상대 강도는 신청 확정 시 시드로 정해 저장하고 뒤늦게 재추첨하지 않는다. 경기력 기본값은 `해당 게임 숙련도×0.5 + 운영력×0.25 + 팀 호흡×0.25`를 반올림한 값이다. 상대별 강도는35~70이며 각 경기에서 그 이상이면 승리, 미달이면 패배로 기록한다. 두 경기 모두 승리한 확정 선수 경로만 우승이다. 한 경기 승리·참가·시점 소개로 우승 경험을 만들지 않는다. 결과와 부족한 점을 복기할 수 있게 표시한다. 실제 기존 대회의 승패를 복사하지 않는다.

공대의 최종 클리어는 현재 게임 숙련도55·연습40·팀 호흡30을 모두 만족하고 검증한 선수 역할인 때만 성립하는 기본안이다. 미달이면 도달한 구간 또는 교육 완주로 기록한다. 서버 축제·가상 전시·식당은 약속한 범위의 작업을 실제 완료한 결과를 기록한다. 작은 보조 목표를 큰 기획 완성으로 바꾸지 않는다.

현재 JSON의 module.recordOutcome은 이 결과 해석기에 연결해야 하는 명시적 효과다. 한국어 결과 문장을 실행 코드에서 해석하지 않는다. 확률로 ‘우승 보너스’를 뽑아 실제 결과를 덮어쓰지 않는다.

## 날짜·기한·강제 엔딩

게임용 콘텐츠 시즌은 수락일부터120일의 기본 참가 창을 사용한다. 실제 역사 서버의 개장일을 2026년 달력에 그대로 복사하지 않는다. 참가 창을 넘는 날짜 선택 시 다음 진행을 할 수 없다는 사실을 먼저 보여준다. 날짜를 건너뛰면 진행하지 않은 활동을 성공 처리하지 않고 기획을 미완료 보관한다. 새 시즌·다음 기회는 별도 초대다. 기한만으로 큰 벌점이나 게임 전체 엔딩을 만들지 않는다.

의상 준비·기존 약속을 지역 자원 초기화와 함께 삭제하지 않는다. 무엔딩2036-01-18 강제 결혼은 모든 콘텐츠보다 우선하고 진행 중 기획을 미완료 스냅샷으로 보관한다. 서버 종료·대회 탈락·식당 시즌 종료는 그 콘텐츠만 닫고 방송일지는 계속한다.

## 경험과 엔딩 연결

모듈 입장·수락·단계 이동만으로 엔딩 경험을 지급하지 않는다. [경험 연결표](rakoko_long_content_bridges.design.json)에 실제 검증·수행 결과가 확인된 때의 EX 생산 조건을 따로 둔다. 참가·선수·지원·진행 역할을 구분하고, gameId가 필요한 경험에는 해당 ID를 보존한다. 경험과 현재 기획 리허설 상태는 다른 데이터이므로 경험이 있어도 새 마무리 기획의 준비는 따로 해야 한다.

예: 마크형 서버에서 **직접 만든 미니게임 부스의 플레이테스트를 실제 완료**하면 EX-024(참여형 미니게임 시험)의 후보가 된다. 단순 건축이나 구경으로 지급하지 않는다. 이 이력은 ‘키몽이 운동회 첫 회’의 경험 조건에 쓸 수 있지만 단골층55·기획력55와 그 엔딩 기획의 현재 준비 조건은 별도로 필요하다. 공대의 같은 게임 설명 시범은 EX-004에, 승인받은 독자 전시의 시험 공개는 EX-016에 연결한다.

콘텐츠를 마쳐도 자동으로 크레딧을 내지 않는다. 관련 기획을 엔딩 후보로 제안하고, 플레이어가 승인한 뒤 수치·경험·준비 조건에 맞는 종결 선택을 해야 일반 엔딩에 도달한다. 기존 일반32결말+강제1결말 수는 이번 추가로 변경하지 않는다.

## 저장·검증·남은 작업

저장에는 moduleId·moduleInstanceId·seasonId·gameId·현재 단계·참여 방송 회차·역할·참가 자격·시점 허용·지역 상태·개별NPC 관계·준비 기획·제출 동의·경기 상대/결과·진행/반복 원 인스턴스·경험 출처·시작/종료일·예약 슬롯을 포함한다. 결과·지역 변화·후속·경험과 처리 명령을 한 트랜잭션으로 저장한다.

검증은 낮은 스테이터스로 모든 모듈을 보조 경로로 마칠 수 있는지, 같은 게임만 숙련도를 공유하는지, 초보 참가가 본선 자격을 만들지 않는지, 한 방송에 진행을 연속 완료하지 않는지, 참가 창 종료·10년 강제 엔딩·재개 시 기획이 보존되는지에 초점을 둔다. 현재는 사건64개와 명시적 선택 효과·제약을 작성한 단계이며 엔진·NPC별 대사·게임별 스킨·경기 해석기·보상 검증의 실제 구현은 남아 있다.

수치가 높은 선택도 선수 자격·현재 역할·준비한 기획 범위·검증한 범위가 다르면 잠긴다. 보조 역할은 보조 자격으로 판단하며 선수 자격을 일괄 요구하지 않는다. 전문 목표를 준비해도 작은 보조 리허설만 했다면 큰 범위 완료로 기록하지 않는다.

방송 자산·운영비·가상 우승 상금은 rakoko_economy_design.md를 따른다. 플랫폼5,000,000원/친선2,000,000원은 실제 상금이 아닌 게임용 수치다. 본선 확정·선수·실제2승·대회완료를 확인한 때만1회 지급하고 지역 자원을 방송 자산으로 환전하지 않는다. 유료 제작 요청은 잔액 부족 시 포기하며 모듈 완료로 구매를 자동 지급하지 않는다.
