# 라코코의 방송일지 기능 명세

2026-11-05 · 설계 v2.2. 수치는 첫 구현의 조정 가능한 기본값이며 플레이 검증을 마친 값이 아니다. 제목은 〈라코코의 방송일지〉를 사용한다. [개발 설정](rakoko_game_rules.design.json)과 [개발 가이드](rakoko_development_guide.md)를 함께 적용한다.

## 범위와 요구사항

주인공 라코코와 다수 키몽이 시청자를 중심으로 방송을 준비하고 선택의 후속 결과를 회수하는 선택형 웹게임이다. 초반에는 라코코 자료에서 각색한 사건의 비중을 높이고 중후반에는 일반화한 외부 사례와 플레이어 자신의 이전 선택에서 이어지는 사건을 확장한다. 같은 라코코의 여러 시즌 결말을 제공한다.

확정: 오컬트 서사·심각한 사건·정체성 교체 제외. 유령 의상은 의상 표현만 허용. 실제 소득·사적 관계·건강을 추정하지 않는다. 의상 4종은 준비→공개→영구 해금, 일부 유출 대응, 방송 준비·방송 중 무료 환복을 적용한다. 다른 팬게임 비교 조사는 재개하지 않는다.

사용자가 아직 선택하지 않은 코너 3칸·포인트 수·시즌 길이·종료 조건은 아래의 기본 제안으로 구체화하되 설정에서 바꿀 수 있게 한다. 실제 인물의 행동 정답을 맞히는 방식은 사용하지 않는다.

## 한 시즌의 실행 흐름

`시작 → 방송 준비 → 코너 편성 → 방송 진행/선택 → 마무리 일지 → 다음 방송 또는 시즌 결산`

방송당 준비 행동 2회·코너 3칸을 기본안으로 둔다. 시작일은 사용자 최종 정정대로 2026-01-18로 고정하고 실제 달력과 방송 회차를 함께 사용한다. 생일은 9월 10일이다. 달력·기념일·진행 구간은 rakoko_calendar_design.md를 따른다. 이전 12회 고정 시즌안은 폐기했다. 진행은 클릭 기반이며 선택을 기다리는 동안 시간이 흐르지 않는다.

준비 행동은 자료 준비·연습·화면 점검·의상 제작에서 선택한다. 코너는 잡담·게임 도전·팬 참여·특별 기획으로 시작한다. 같은 코너를 반복 편성할 수 있지만 같은 사건을 반복 보상하지 않는다. 의상 정식 공개는 특별 기획 1칸을 사용한다. 예약 시 해당 회차의 한 칸을 확보하고, 해제하면 돌려준다.

준비 완료 후 편성을 확정하면 방송을 시작한다. 한 코너에는 주 사건 1개, 즉시 선택 1회가 기본이다. 후속 사건이나 공개가 있으면 무작위 사건을 대체하며 덧붙여 무한히 늘리지 않는다. 끝에는 대표 장면 1개를 골라 일지에 남긴다. 나머지 기록도 자동 저장하여 대표로 고르지 않은 사건의 약속이 사라지지 않게 한다.

## 화면과 사용자 행동

|화면|주요 정보|주요 행동|
|---|---|---|
|시작/이어하기|저장 회차·현재 의상·진행 요약|새 게임, 이어하기, 저장 내보내기/가져오기|
|방송 준비|남은 행동·진행 중 의상·약속·다음 코너|준비 행동, 환복, 편성, 시작|
|방송|현재 코너·라코코 전신·선택 카드|선택, 환복, 로그, 설정|
|의상함|현재 옷·해금/준비 상태|무료 환복, 준비 시작, 공개 예약|
|방송일지|회차별 선택·후속 연결·대표 장면|장면 선정, 지난 기록 보기|
|시즌 결산|대표 장면·도전/기획/회수 기록|결말 보기, 기록 보관, 새 시즌|

잠긴 선택은 이유를 설명한다. 확률 결과가 있는 선택은 위험이 있다는 사실과 설정된 확률을 선택 전에 보여준다. 일지와 설정을 여는 것은 행동을 소모하지 않는다. 모바일에서도 선택지와 환복을 사용할 수 있고 호버만으로 기능을 숨기지 않는다. 텍스트 크기·음량·동작 줄이기 설정을 둔다. 조명 깜박임은 사용하지 않는다.

## 상태와 성장

|종류|값|사용|
|---|---|---|
|방송 단위|준비 행동 잔여·코너 순서·현재 사건|방송 종료 시 초기화|
|시즌 단위|자료/연습 누적·완료 기획·회수한 약속|선택 가능성과 결산에 반영|
|진행 목록|도전·약속·의상 준비·후속 사건|이행/변경/보류 상태를 구분|
|외형|해금 의상·착용 의상|선택 수치와 분리|
|기록|사건 인스턴스·선택·결과·대표 장면|일지·재개·중복 방지|

보유 자산은 가상의 방송 자금으로 추가한다. 새 게임3,000,000원, 방송 수입과 운영비·유료 사건 지출을 거래 장부로 저장한다. 실제 소득을 추정하지 않으며 자동 부채를 만들지 않는다. 잔액이 부족하면 유료 선택은 잠기고 해당 사건을 포기한다. 수치는 rakoko_economy.design.json을 따른다. 팬 수 등의 숫자는 필수 성장 축으로 확정하지 않는다. 의상마다 성능 우열을 부여하지 않으며 같은 옷을 입어도 불이익을 주지 않는다.

## 사건 선정과 콘텐츠 구조

일반 사건은 `출처 기반 각색`, `외부 구조에서 만든 창작`, `독자 창작`으로 이력을 구분한다. `이전 선택의 후속`은 별도 대기열이다. 게임에서는 출처 기반 사건도 실제 방송을 그대로 재현한 전기물로 표현하지 않는다. 일반 사건은 출처 풀을 먼저 선택하고 그 안에서 주제 배수를 적용해 카드 하나를 뽑는다. 양쪽에 후보가 있을 때 라코코 각색/창작 출처 비율은 초반 90/10, 중반 55/45, 후반 40/60이다. 외부 구조에서 만든 창작과 독자 창작은 추첨에서는 한 풀로 합친다. 선택한 출처 안에서 게임 플레이 주제의 상대 가중치는 초반 0.35배, 중반 1배, 후반 4배다. 다른 주제는 1배다. 적격 후보끼리 정규화하며 실제 방송 빈도를 뜻하지 않는다. 약속 후속·예약 공개는 이 추첨과 별도 우선 순위로 배치한다.

준비 화면은 예약 공개 칸을 먼저 표시한다. 기념일을 수락하면 빈칸에 배치하거나 플레이어가 일반 코너를 지정해 교체한다. 자리가 없으면 늦은 축하로 미루거나 일지에만 남긴다. 공개 예약과 미해결 선택은 덮어쓰지 않는다. 편성 확정 뒤 우선 순위는 미해결 선택 재개 → 해당 칸의 예약 공개 또는 수락한 기념일 → 기한 도래 후속 → 해당 코너 적격 일반 사건 → 반복 가능한 일상 사건이다. 한 슬롯을 채우면 다음 사건은 다음 슬롯으로 이동한다. 의상 공개 슬롯에서는 유출을 추첨하지 않고 공개를 진행한다. 미래 공개를 준비 중인 의상은 다른 일반 코너의 방송당 첫 적격 시점에서만 유출을 검사한다.

사건 조건은 필요한 코너·선행 사건·준비 상태·회차 범위·중복/재등장 제한으로 구성한다. 실제 자료의 인물명·음성·이미지를 외부 사건에서 자동 가져오지 않는다. 사건 29개와 추가 관찰 12개는 별개이며 단순 합산해서 플레이 가능 카드 수로 보고하지 않는다.

|사건 필드|의미|
|---|---|
|id / revision / familyId|정의 ID·버전·유사 소재 묶음|
|sourceRefs / provenance|출처와 각색 구분, 검증 상태|
|eligibility / tags|등장 조건·코너|
|choices|ID·텍스트·조건·비용·결과 표|
|effects / followups|즉시 결과·미래 사건 생성|
|cooldown / maxOccurrences|재등장 제한|
|assets|의상 전신·공용 배경 등 연결|

콘텐츠 부족 시 빈 화면이나 강제 종료 대신 일상 사건으로 이어간다. 일상 사건은 중복 보상 없이 준비를 정리하거나 다음 방송 계획을 바꾼다. 초기 제작 목표는 각 코너에 반복 가능 일상 2종 이상, 사건 묶음마다 최소 1개 후속 또는 종료 결과다. 이 수량은 확보 완료 수량이 아니다.

## 약속·후속 사건

약속은 대상·발생 회차·도래 회차·상태·원 사건 인스턴스로 식별한다. 완료·변경·보류는 서로 다른 기록이다. 보류에 무한 벌점을 주지 않고 다음 회차에 다시 편성할 수 있다. 한번 완료한 약속은 같은 후속 키로 다시 생성하지 않는다. 대표 장면 선택 여부는 후속 발생 조건에 영향을 주지 않는다.

선택을 저장하는 트랜잭션에서 후속을 한 번 생성하고 다음 준비 화면에서 표시한다. 기본 도래 시점은 다음 방송이다. 도래 회차가 빠른 순서, 같으면 생성 순서로 처리하며 자리가 없으면 대기시킨다. 결산 직전에도 미완료 약속을 강제로 완료 처리하지 않는다.

## 의상 기능 통합

상세는 `rakoko_outfit_feature_design.md`, 설정은 `assets/events/outfit-reveals/rules.design.json`을 따른다. 공개 후 무료 환복은 외형 상태만 변경한다. 공개는 해금만 하며 자동 환복하지 않고 ‘지금 입기’를 무료로 제공한다. 공개 시연은 별도 표시로 처리하고 이전 착용 의상은 유지한다.

의상 준비 행동 1회에 진행도 +25를 초깃값으로 둔다. 즉 준비 행동 총 4회를 요구하지만 다른 준비와 나눠 진행할 수 있다. 취소하면 이미 쓴 행동은 돌려주지 않으며 진행도는 보존한다. 동시에 준비하는 의상은 기본 1종, 다른 의상을 선택하면 기존 준비를 일시 중단하고 진행도·유출 기록은 보존한다. 공개하지 않은 의상은 다음 시즌으로 자동 해금하지 않는다.

유출 검사는 `방송 ID + 의상 ID`별 한 번이며 성공·실패 판정을 모두 저장한다. 실제 일부 유출 사건이 한번 발생한 의상은 추가 유출을 만들지 않는다. 사건 대응이 끝나기 전에는 다음 코너로 가지 않는다. 수습 성공/티저는 준비·예약 유지, 조기 공개는 기존 공개 슬롯을 소개/팬 참여 코너로 교체한다. 공개 예약 회차보다 늦어진 상태로 준비를 바꾸면 UI에서 새 회차를 지정하도록 한다.

## 시즌 결산

일반 엔딩 사건이 발생하지 않으면 계속 방송한다. 단, 엔딩을 한 번도 보지 않은 run은 만 10년인 2036-01-18에 가상의 키몽이 NPC 한 명과 결혼하는 강제 엔딩으로 종료한다. 주년 축하는 별도 달력 이벤트이며 자동 엔딩이나 장 전환을 만들지 않는다. 첫 1주년부터 방송 종료 시 검사한다. 완료 연수 1년 5%, 이후 해마다 +3%p, 상한 35%다. 미당첨 뒤 최소 30일 간격이며 날짜 도약 시 소급 검사하지 않는다.

당첨하면 현재 기획의 조건에 맞는 엔딩 사건 하나를 제시한다. 각 사건의 추가 조건을 갖춘 종결 선택을 고르면 고유 결말로 이어지고 계속 선택은 90일 뒤 검사 재개로 돌아간다. 엔딩 확정 뒤 같은 일지로 계속하면 다음 방송에서 새 장을 시작하고 365일 동안 엔딩 검사를 쉰다. 일반 방송 후 사건의 20% 판정과 별개다. 마무리 상태 저장 → 엔딩 검사/사건 선택 → 결과를 포함한 일지 확정 → 일반 진행 또는 크레딧 순서다.

[엔딩 사건 16종·결말 32종](rakoko_ending_routes.md)을 채택한다. 준비 플래그는 선행 기획·리허설·검수 사건에서 만들고 해당 기획 ID에 묶는다. 선택의 경험·준비가 충족된 승인 마무리 기획만 자연발생 후보에 넣고, 스테이터스 부족은 사건을 숨기기보다 선택 비활성화로 표시한다. 완전히 준비되면 마지막 특집을 예약해 확정 진행할 수도 있다. 일반 엔딩은 명시적 종결 선택으로만 확정한다. 이름 목록에서 해금한 결말을 고르는 방식을 폐기했다. 생애 종료·환생·다른 캐릭터 전환은 사용하지 않는다. 누적 목표 9종은 [업적](rakoko_achievement_design.md)이며 엔딩 조건과 확률에 관여하지 않는다.

새 장은 옷장·준비·약속·날짜·업적·도달 결말·수치·경험·재등장 기록을 유지하고 현재 기획 story 상태만 새 ID로 시작한다. 별도 새 게임만 새 runId와 기본복으로 2026-01-18부터 시작한다. 상세 판정·저장은 [엔딩 설계](rakoko_ending_design.md)를 따른다.

## 저장·재개와 기술 경계

화면은 상태를 표시하고 명령을 발행한다. 사건 엔진이 조건/선택을 검증하고 상태 변경·기록·난수 결과를 한 번에 저장한다. 아트 파일 목록은 manifest, 게임 규칙은 버전이 있는 데이터로 분리한다. 웹 프레임워크·배포 플랫폼은 아직 확정하지 않는다.

세이브는 `schemaVersion, contentVersion, runId, revision, phase, broadcastId, slotIndex, progress, pendingEvent, queue, outfits, equippedOutfitId, journal, rngState, appliedCommandIds`를 가진다. 사건 정의와 별도로 인스턴스에 선택지·판정 결과를 저장한다. 콘텐츠 업데이트로 진행 중 사건이 사라져도 저장된 스냅샷으로 재개한다.

저장은 IndexedDB 단일 트랜잭션으로 진행 상태·명령 ID·기록을 갱신하고 직전 정상 저장을 복구용으로 보존하는 방식을 기본안으로 둔다. 저장 실패 시 성공 화면이나 다음 코너로 진행하지 않고 재시도/내보내기를 제공한다. 난수는 클라이언트 시드 기반이며 재개 안정성을 위한 장치다. 사용자의 저장 파일 편집까지 막는 보안 기능으로 주장하지 않는다.

다중 탭에서는 runId/revision 비교로 충돌을 감지하고 오래된 탭의 쓰기를 거절한다. 불러올 때 알 수 없는 의상 ID는 기본 의상으로 대체하되 원본 저장을 보관한다. 세이브 가져오기는 크기·스키마·숫자 범위·참조 ID를 검증하고 텍스트를 HTML로 실행하지 않는다. 앱 업데이트로 구버전 세이브를 이관할 수 없으면 덮어쓰지 않고 내보내기와 새 시즌을 제공한다.

## 구현 순서와 완료 기준

|단계|범위|완료 기준|
|---|---|---|
|1|상태·명령·저장·일상 사건|1회 방송을 완료하고 중간 종료 후 정확히 재개|
|2|편성·준비·후속·일지|이전 선택이 다음 방송으로 연결되고 기한 초과가 보존됨|
|3|4종 의상·유출·무료 환복|정식/조기 공개·중복 방지·예약 교체 경로 확인|
|4|시즌 결산·콘텐츠 검수|초반부터 결산까지 사건 부족·막힘 없이 진행|
|5|모바일·접근성·에셋 통합|키보드/터치 조작, 이미지 실패 대체, 글자 가독성 확인|

전체 구현 착수에 필요한 기능 경계는 정의했지만, 실제 말투·원음 검증 완료와 전체 사건 채택이 끝났다는 뜻은 아니다. 출처 검증이 부족한 문장은 직접 인용으로 쓰지 않고 승인 전 콘텐츠에는 상태 표시를 유지한다.

## 추첨 규칙 v1.4

추첨 대상·코너·출처·선행 조건은 [통합 추첨 목록](rakoko_draw_pool.design.json)을 사용한다. RK는 조사 원본 ID, CE는 창작 설계 ID, RA는 추가 관찰을 각색한 ID다. trigger가 random인 항목만 일반 풀에 넣는다. 코너와 조건을 만족하는 후보 중 소재별 반복 정책·간격·원자료 1회 제한 및 직전 두 방송과 현재 방송의 group 제한을 적용한다. 시작일부터 경과한 날짜로 0~90일, 91~240일, 241일 이후 구간을 정한다. minElapsedDay를 충족한 후보에서 출처 풀을 먼저 뽑고 그 안에서 topic에 따른 상대 가중치로 한 항목을 선택한다. 라코코의 게임 방송은 두 축에 모두 해당한다. 후반 후보 고갈을 줄이기 위해 창작 게임 소재 CE-017·018·022·029는 경과 241일부터 등장하는 조정안으로 둔다. 방송 장애처럼 게임 코너에서도 일어나는 일반 사건은 주제 보너스를 받지 않는다. 한쪽 풀이 비면 다른 쪽을 쓰고, 양쪽이 비면 해당 코너의 일상 둘을 교대한다. 같은 family의 RK와 CE는 발생·간격을 공유한다. RK는 run당1회이고 반복형 CE는 최소 간격 뒤 다시 가능하다. 고정·후속 코너는 별도 처리한다. [1년 공급 검토](rakoko_draw_review.md)에 보강 전후 결과와 모형 가정을 기록했다.

## 인카운터 확장 v1.2

사용자가 앞선 돌발 사건의 반영과 방송 상황 창작을 허용했다. rakoko_encounter_catalog.md/.json에 12분류·72개 창작 설계를 추가했다. 조건·선택·결과·후속·재등장 제한을 기록했다. 유출 엔진 훅·결과 반응·예약 변주·조건 후속·방송 후 사건은 일반 랜덤과 구분한다. 기존29사건과 주제가 겹치므로 101개 독립 사건으로 합산하지 않는다.

추가 조사03은 자막 관찰12개/출처10편이며 창작72개와 별개다. 원음·화자 검증 완료를 뜻하지 않는다. 일반 사건180종/후속60종은 초기 분량 목표이며 아직 미달이다. 코너별 적격 풀과 기능군 중복을 검토해야 한다. 제목만 다른 사건 수로 분량 충분을 판정하지 않는다.


## 스테이터스·실행 잠금·반복 최신 기준

[스테이터스](rakoko_status_design.md)의 0~100 다섯 축과 [엔딩 요구표](rakoko_ending_requirements.design.json)를 적용한다. 일반 32결말마다 관련 수치2개·EX경험1개·기획 준비를 요구한다. 게임 역량과 경험은 현재 기획의 게임 ID에 한정한다. 업적은 수치·경험을 자동 생성하지 않는다.

312개 일반 선택의 연결은 rakoko_event_play_rules.design.json이다. 기본 선택은 열어두고 전문 선택만 관련 능력으로 제한한다. 부족한 선택은 보이되 실행할 수 없으며 실제값/필요값과 준비·경험 부족을 설명하고 제출 시 재검증한다. 무료 환복과 유출 대응의 확정 사용자 요구는 수치로 막지 않는다.

창작 일반55참조는 반복 또는 새 맥락 재등장을 허용한다. RK·RA 특정 실화 각색은 같은 run 1회, 약속·도전 결과·기념일·의상은 원 인스턴스/발생 키별 1회다. family 최소 간격·같은 기능군 간격·첫 보상 중복 방지와 변주를 함께 적용한다. 상세는 [반복 설계](rakoko_repeat_event_design.md)를 따른다.

총 엔딩은 일반16사건/32결말과 별도 무엔딩10년 강제1사건/1결말이다. 강제 엔딩은 수치·선행 경험을 우회하고 계속하기가 없다. 이전에 일반 엔딩을 봤다면 적용하지 않는다. 구체적인 날짜 도약·저장·배우자 고정 규칙은 엔딩 설계를 따른다.


## 장기 콘텐츠 추가 v1.0

장기 서버·공대·대회·협동 시리즈8종을 추가한다. 조사와 사건은 [장기 콘텐츠](rakoko_long_content_design.md)를 따른다. 새64사건/192선택은 활성 모듈에서만 선택하고 일반105참조에 무조건 섞지 않는다. 한 방송3칸·준비2행동을 공유하고 최대2칸·단계전이1번을 적용한다.

플랫폼 주최 대회와 스트리머 주최 친선전을 구분하고 초청·신청·참가 자격·스크림·중계 역할·실제 승패를 저장한다. 본선 참가 자격 없이 우승하는 결과를 금지한다. 소규모·교육·보조 경로도 진행할 수 있다. 모듈 종료는 게임 엔딩을 만들지 않으며 검증된 결과만 경험으로 연결한다.

새 모듈의 지역 상태·참가 기한·역할·경기·기획은 별도 인스턴스에 저장한다. 전역 성장과 같은 게임 숙련도·의상·약속은 보존한다. 무엔딩10년 강제 엔딩이 우선한다.


## 방송 자금 경제 v2.0

경제 원본은 economy.cash다. 기존 능력 수치0~100과 별도로 표시하고 같은 일지에서 보존한다. 초기 상태3코너 방송 순수입270,000원, 기본 운영비30,000원이며 시작 수치를 사용한 명시적 공식으로 일회 정산한다. 앱 종료나 날짜 이동은 수입/고정비를 만들지 않는다.

유료 사건16종/48선택과 의상 준비500,000원/행동+25를 추가한다. 잔액·원 조건을 제출 시 재검증하고 돈/결과/기록을 한 번에 저장한다. 잔액 미달은 포기이며 유료 진행도·구매·성공 경험을 주지 않는다. 공개 의상 환복과 강제10년 결혼은0원이다. 게임 내 서버 화폐와 방송 자금은 구분한다. [경제 설계](rakoko_economy_design.md)를 따른다.

경제v2.0: 성장지표min(인지도,단골층) 단계0/25/45/65/85의 배율1/2/5/12/25를 기본 수입과 운영비에 적용한다. 최고해금단계와 방송시작스냅샷을 보존한다. 90/95의 정상방송 순수입14,500,000원, 의상준비총2,000,000원, 주요제작비5,000,000~80,000,000원이다. 인터넷공개사례와 게임값의 구분은 rakoko_economy_research.md를 따른다.


## 키몽이 다수 반응

키몽이는 여러 시청자 집단이다. 평상시 반응은 3~5줄·최소 두 가상 화자, 조용한 장면은 0~2줄을 기본안으로 한다. 한 화자의 해설로 집단을 대체하지 않으며 모든 키몽이가 같은 의견을 가진 것으로 처리하지 않는다. 실제 채팅의 닉네임·프로필·개인 성격을 재현하지 않는다. 결혼 상대는 집단 중 한 가상 NPC이며 후보 8개 ID가 전체 팬 수는 아니다.

대사 정보는 현재 공개 범위·결과 확정·같은 run의 경험/약속으로 제한한다. 반응 표시에는 새 행동·필수 클릭·대기 시간을 쓰지 않는다. 사건 결과와 반응 템플릿/화자/순서/변수를 함께 저장해 재접속·재감상 때 바뀌지 않게 한다. 반응은 기계적 보상을 직접 발생시키지 않는다.

[집단 대사 가이드](rakoko_kimongi_dialogue_guide.md), [대사 설정](rakoko_kimongi_dialogue.design.json), [1차 실제 채팅 표본](rakoko_kimongi_chat_research.md), [창작 예시](rakoko_kimongi_dialogue_examples.md)를 참조한다. 현재는 조사·설계 단계로 UI와 선택기는 미구현이다.
