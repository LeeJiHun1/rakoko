# 기획 검토 — "왜 평이한가"와 도파민 루프 개선안

> 작성 2026-11-05 · 근거는 `src/data/catalog.json` 집계와 엔진 시뮬레이션 실측 (스크립트: 작업 임시폴더 `design-stats.mjs`, `design-sim.mjs`)
> 이 문서는 **제안**이다. 규칙 변경은 §4 결정 후 진행하며, 변경 시 골든 테스트 기준 갱신(`UPDATE_GOLDEN=1`)과 이유 기록이 필요하다.

## 1. 진단 — 왜 평이한가 (실측)

### 1-1. 선택이 결과를 바꾸지 않는다 — 가장 큰 원인

| 지표 | 실측 |
|---|---|
| 일반 사건 / 선택지 | 80개 / 236개 |
| 선택지별 능력 상승 합계 | **236개 전부 정확히 +2** |
| 능력이 내려가는 선택 | **0개** |
| 위험(`risk`)이 있는 선택 | **0개** (위험은 의상 유출 사건 1곳뿐) |
| 한 사건 안의 선택지 가치가 모두 같은 사건 | **80개 중 80개** |
| 결과 문구(`outcome`) 길이 | 중앙값 **8자**, 최소 3자 (예: "방해 종료", "자료 전체 표시", "온라인 도전 보류") |

- 모든 선택이 "어느 능력에 +2를 줄까"의 차이뿐이고, 실패·대성공·손실이 없다. 그래서 **선택해도 긴장이 없고 결과를 기대할 이유가 없다**.
- 결과 문구가 시스템 로그처럼 짧아서 "무슨 일이 벌어졌는지"를 보여 주는 장면이 없다.
- 실패 가능성은 의상 유출의 "장난스럽게 수습"(10/25%)과 대회 경기 패배, 두 군데에만 있다.

### 1-2. 능력치가 금방 꽉 차서 의미가 없어진다

기본 흐름("7일 뒤" 반복, 준비=자료+연습, 선택은 무작위)을 20개 시드로 시뮬레이션한 결과(평균):

| 방송 수 | 날짜 | 인지도 | 단골 | 기획 | 운영 | 숙련 | 자금 |
|---|---|---|---|---|---|---|---|
| 10 | 2026-03 | 34 | 57 | 48 | 40 | 41 | 779만 |
| 30 | 2026-08 | 43 | **99** | **89** | 56 | **100** | 3,393만 |
| 52 | 2027-01 (1주년 직전) | 47 | 100 | 100 | 61 | 100 | 7,990만 |

- 기획 결말이 요구하는 능력치는 최대 70인데, 약 30회 방송이면 대부분 충족된다.
- 그런데 마지막 특집은 **1주년(약 52회 방송)부터** 열린다. 결과적으로 **30~52회 구간 약 20회 방송은 오르는 것도 없고 목표도 없는 "대기 시간"**이다.
- 성장 상한(방송당 능력별 +6)이 "많이 해도 차이가 없다"는 체감을 키운다.

### 1-3. 돈이 쌓이기만 하고 쓸 곳이 없다

- 수입: 방송 1회 순수입이 시작 단계 약 25만 원에서 최상위 단계 약 1,375만 원까지 오른다. 52회 시점 평균 잔액은 약 8,000만 원이다.
- 지출처:
  - 의상: 4벌 × 4회 × 50만 원 = 총 800만 원
  - 구매 16종(가격 1.5만~8,000만 원, 중앙값 50만 원): 효과가 `cash.debit`·`purchase.record`뿐이고 **게임에 미치는 효과가 없다**. 사건 RK-026 등장 조건 1개를 빼면 사는 의미가 없다.
- 결과적으로 **잔액이 위협도 보상도 되지 못한다**. 대회 상금(200만·500만 원)도 이미 수천만 원이 쌓인 상태에서는 체감되지 않는다.

### 1-4. 무작위 보상과 희귀 이벤트가 없다

- 무작위 요소: 사건 추첨, 의상 유출(3~8%), 결말 제안 확률(30일마다 5~35%), 대회 상대 준비도. **"대박"이 터지는 순간이 없다.**
- 희귀도 개념이 없다. 사건 80종 중 55종이 반복형이고, 반복될 때 문구 변형이 1개뿐이다(`authoredVariantCount: 1`).

### 1-5. 목표가 잘 보이지 않는다

- 결말 32종 가운데 목표 화면에서 추천하는 건 3종이고, 나머지 29종은 접힌 목록 안에 있다. "다음에 열 수 있는 결말"이나 진행률이 없다.
- 결말 수집 화면도 "만난 결말 N/33"과 만난 것의 목록만 보여 준다.

### 1-6. 키몽이 채팅이 선택의 "질"에 반응하지 않는다

- 채팅 반응은 28개 맥락 × 약 9줄이다(`src/data/chat.js`). 맥락은 **사건 종류(기획·기념일·경기 승패 등)와 선택지 문구 키워드**로만 정해진다.
- 일반 사건에서는 잘했는지 못했는지에 따라 반응이 달라지지 않는다. 채팅이 폭주하거나 대박 연출이 나오는 순간이 없다.

### 1-7. 결과 화면 피드백이 약하다

- 결과 화면에 보이는 건 "능력 +N" 태그와 채팅 3줄이다. 정산 화면은 수입 숫자 한 줄이다.
- 시청자 수, 방송 등급, 역대 기록 갱신처럼 **보상을 숫자로 체감하는 장치가 없다**.

**요약:** 지금은 "선택 → 무조건 +2 → 같은 화면" 루프입니다. 기대(불확실성), 보상의 크기 차이, 가까운 목표, 기록 갱신이라는 네 가지 도파민 장치가 모두 비어 있습니다.

## 2. 개선안 — 도파민 루프

목표 루프: **준비(확률을 올린다) → 위험-보상 선택 → 등급이 갈리는 결과와 채팅 폭주 → 시청자·후원 숫자 → 기록 갱신·미션 달성 → 다음 목표**

| 우선 | 안 | 무엇을 / 왜 | 붙는 곳 (새 구조) | 난이도 | 제약 충돌 |
|---|---|---|---|---|---|
| **A1** | 위험-보상 선택 | 선택지마다 성공 확률을 표시하고 결과를 **대성공 / 성공 / 아쉬움** 3단계로 나눈다(예: 대성공 +4·채팅 폭주, 아쉬움 +0·코믹 연출). 준비 행동(자료·점검·연습)이 확률을 올려 **준비에 의미**가 생긴다. | `engine/choices.js` `KIND_EFFECTS.general` + `random(s)`; 확률 계산은 새 `engine/outcome.js`; 데이터는 `scripts/compile-content.mjs`가 선택지에 `difficulty` 부여 | 중 | 실패를 "심각한 사건"으로 쓰지 않는 조건에서만 충돌 없음 |
| **A2** | 방송 등급·시청자 수 | 정산 때 **동시 시청자 수(최고치)**와 **S~C 등급**을 낸다. 역대 최고를 갱신하면 "NEW RECORD" 연출. 키몽이가 여러 명이라는 설정과도 맞는다. | `engine/economy.js` `settleIncome` 옆에 `rateBroadcast()`; `journal[]`에 `viewers`·`grade` 기록; UI `views/wrap.js` | 하~중 | 없음 (경험·결말 조건에는 넣지 않음) |
| **A3** | 결말 힌트·진행률 | 목표 화면에 결말별 진행 막대(능력·경험·1주년 조건)와 "곧 열리는 결말 TOP3"를 보여 준다. 잠금 사유는 이미 `finaleLocks`·`unmet`에 있다. | UI `views/projects.js`·수집 대화상자; 엔진 변경 없음 | **하** | 없음 |
| **A4** | 채팅 반응을 결과에 연동 | 대성공이면 "폭주" 맥락(줄 수↑·빠른 연출), 아쉬움이면 위로·드립 맥락. | `data/chat.js` `chatContext`에 결과 등급 인자; `engine/reactions.js` 줄 수 가변 | 하 | 없음 (반응 기록이 저장되므로 재추첨 없음 유지) |
| **B1** | 후원 랜덤 이벤트·대박 | 방송 중 확률로 **후원 사건**이 터진다(소액 자주, 대박 드물게). 등급·시청자가 높을수록 확률이 오른다. 금액에 따라 리액션 선택지가 갈린다. | 새 `engine/events/donation.js` + `events/next.js` 우선순위에 삽입; 금액은 `economy.js` | 중 | 방송 진행 중에만 발생하고 날짜 건너뛰기로는 생기지 않는 조건에서 충돌 없음. 실제 플랫폼 화폐명(예: 치즈)은 쓰지 않는다 |
| **B2** | 돈의 쓸모 — 구매 효과 | 장비·외주 구매가 **확률 보정**(A1)이나 **시청자 보정**(A2)을 다음 N회 방송 동안 준다. 돈이 "확률을 사는" 자원이 된다. | `engine/economy.js` 구매 기록에 `buff` 추가; `outcome.js`가 읽음; 데이터는 `moneyEvents.effects` | 중 | "잔액 부족 시 무료 지급 금지"는 유지 (기존 검사 그대로) |
| **B3** | 연속 성공 콤보·출석 스트릭 | 한 방송에서 3코너 연속 성공 시 **콤보 보너스**. 방송 간격 ≤7일이 이어지면 스트릭 배지와 시청자 보정. | `engine/broadcast.js` `settle`·`beginNextBroadcast`; 상태에 `streak` | 하~중 | 스트릭은 방송 횟수 기준. 날짜 건너뛰기로 스트릭이 오르는 일은 없어야 한다(끊기는 것만 허용) |
| **B4** | 주간/월간 미션 | "이번 달: 게임 도전 대성공 2회·후원 1회" 같은 3개 미션. 달성하면 시청자·자금 보상과 도장. 30~52회 대기 구간을 메운다. | 새 `engine/missions.js` + 명령 등록표에 추가; UI 준비 화면 카드 | 중 | 보상이 경험·결말 조건을 대신하면 안 된다 (일반 결말 조건 규칙) |
| **B5** | 페이싱 조정 | 능력치가 30회에 다 차는 문제. ①결말 시기를 앞당기거나 ②능력 요구치를 올리거나 ③성장 곡선을 늦춘다. | `engine/constants.js`, `engine/project.js` `finaleLocks`, `engine/ending.js` | 하 (수치) / 결정 필요 | 일반 결말의 "실제 경험·기획·수치·종결 선택" 조건은 유지. 10년 강제 결말 조건은 건드리지 않는다 |
| **C1** | 희귀 사건·도감 | 사건에 희귀도(일반/희귀/전설)를 붙이고 낮은 확률로 등장시킨다. 일지에 **사건 도감**(발견 N/80, 희귀 표시). | `engine/events/general.js` 가중치에 `rarity`; UI `views/journal.js` | 중 (희귀 사건 문구 작성 필요) | 내용이 오컬트 서사가 아닌 조건에서 충돌 없음 |
| **C2** | 결과 연출 | 숫자 카운트업, 시청자 그래프, 대성공 화면 흔들림·반짝임, 효과음 3종. "동작 줄이기" 설정을 존중한다. | UI `views/result.js`·`wrap.js`, CSS, `ui/feedback.js` | 하~중 | 없음 |
| **C3** | 라이벌·합방 대결 확장 | 지금 대회 모듈에만 있는 승패를 일반 게임 코너로 넓힌다(가상 동료와 점수 대결). | `engine/module.js`·`events/module-events.js` | 상 | 실존 인물을 등장시키지 않고 가상 동료로만 쓰는 조건에서 충돌 없음 |
| **C4** | 결과 문구 보강 | 중앙값 8자인 결과 문구를 1~2문장 장면으로 다시 쓴다(등급별로 3종). | `outputs/*.design.json` → `compile-content.mjs` | 중 (작문량 많음) | 없음 |

**추천 순서:** A3·A2·A4·C2(규칙 영향이 작고 체감이 큼) → A1(핵심 재미) → B1·B2(돈과 무작위 보상) → B3·B4·B5(장기 동기) → C1·C3·C4(콘텐츠)

## 4. 사용자 결정 필요 사항

**Q1. 실패·손실을 어느 수위까지 넣을까?** (A1·B1에 영향)
- (a) 실패 없음, 대성공만 추가 — 안전하지만 긴장감 효과가 작음
- **(b) 가벼운 실패: 그 코너 성장 0 + 코믹 연출 + 위로 채팅 ← 추천.** 손해는 작고 "될까?" 하는 긴장은 생김. 팬게임 톤 유지
- (c) 실제 손실: 능력·시청자·자금 감소 — 도파민은 크지만 스트레스·이탈 위험

**Q2. 확률을 보여 줄까, 숨길까?**
- **(a) 확률 공개 + 준비·장비로 확률 상승 ← 추천.** 준비 행동과 돈에 의미가 생기고, 결과가 공정하게 느껴짐
- (b) "쉬움/보통/어려움" 같은 대략 표시만
- (c) 숨김 — 놀라움은 크지만 선택 근거가 사라짐

**Q3. 한 판(첫 결말까지)의 목표 길이는?** (B5)
- (a) 현행 유지(약 52회, 1주년) + 미션으로 대기 구간 메우기
- **(b) 약 20~25회: 첫 결말을 반년(200일)부터 허용, 능력 요구치 소폭 상향 ← 추천.** 능력이 다 차는 30회 전에 첫 결말이 나옴. 다시 하기 동기 강화
- (c) 약 12회 이하 짧은 판 + 회차 반복 중심

**Q4. 후원·시청자 수 같은 실제 방송 요소를 숫자로 보여 줄까?** (A2·B1)
- **(a) 시청자 수 + 가상 후원 둘 다 ← 추천** (실제 플랫폼 화폐명은 쓰지 않음, 가이드라인 확인 조건)
- (b) 시청자 수만 (후원 묘사 부담 회피)
- (c) 둘 다 넣지 않고 등급만

**Q5. 돈을 어떻게 의미 있게 만들까?** (B2)
- **(a) 구매에 실제 효과 부여(확률·시청자 보정, N회 지속) ← 추천**
- (b) 수입 곡선을 낮춰 의상 비용을 무겁게
- (c) 둘 다

**Q6. 연출에 어디까지 투자할까?** (C2)
- **(a) CSS·효과음 수준(카운트업, 흔들림, 반짝임, 채팅 폭주) ← 추천.** 외부 패키지 없이 가능
- (b) (a) + 대성공·후원 컷인 이미지 — 이미지 제작이 필요하고 AI 생성 이미지 가이드라인 확인이 조건
- (c) 최소(숫자만)
